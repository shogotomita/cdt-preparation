# 解説生成方針

過去問 JSON（`public/data/questions/*.json`）の `explanation` / `overallExplanation` を書くときの方針。  
参照実装: [`2025-hou.json` 問1](../public/data/questions/2025-hou.json)

---

## 目的

- 正誤判定だけでなく、**試験範囲の知識をその問で一通り押さえられる**解説にする
- ひっかけ（言い換え・似た制度・条文にない事項）を明示する

---

## フィールドごとの方針

### 1. 各選択肢 `choices[].explanation`

| ルール | 内容 |
|--------|------|
| 書き出し | 「正解。」または「不正解。」で始める |
| 分量 | 1〜3文。簡潔に |
| 必須 | なぜその正誤になるかの根拠（条文名・制度名・対比） |
| ひっかけ | 不正解は、近い正しい文言や混同しやすい概念があれば指摘する |

**良い例（不正解）**

> 不正解。法第１条に「公正な競争の確保」という文言はない。近い概念として定められているのは「旅行業務に関する取引の公正の維持」であり、「競争」ではない。

**避けること**

- 「違うから不正解」だけ（根拠なし）
- 選択肢本文の言い換えだけの繰り返し
- 未確認の条文番号・数字の推測

### 2. 全体解説 `overallExplanation`

試験勉強用のまとめ。**選択肢に出ていない論点も載せる。**

推奨セクション（この順）:

```
【条文/制度】     … 関連条文の要旨または重要部分（必要なら要旨＋要点）
【要点の羅列】   … 定義・要件・例外・列挙事項を漏れなく整理
【計算過程】     … 計算問題の場合（下記「計算問題」参照）。公式→代入→途中式→答え
【選択肢との対応】… ア〜エ（A〜D）がなぜ正誤か、短く対応づけ
【学習メモ】     … 選択肢外の重要事項、頻出のひっかけ、隣接制度との違い
```

見出し名は問の内容に合わせて変えてよい（例: `【目的として定められている３つ】`）。制度説明だけの問では `【計算過程】` は省略する。

**必須**

- その問が問う条文・制度の「全体像」（列挙型なら全項目）
- 選択肢に無いが学習すべき項目を明示する
- 正解キーと矛盾しないこと
- **計算問題では、答えだけでなく計算方法・途中式を全体解説に含める**

**問1での具体例**

- 法第１条の目的は3つ → 選択肢は「安全」「利便」のみ
- 全体解説では選択肢に無い「旅行業務に関する取引の公正の維持」も羅列する
- あわせて条文前段の「手段」（登録制度・適正運営・団体活動）も載せる

### 3. 計算問題（主に国内旅行実務）

運賃・料金・割引・手数料などの数値を求める／選ばせる問。

**全体解説に必ず含めること**

| 要素 | 内容 |
|------|------|
| 使うルール | 適用する規則・約款・運賃計算の原則（例: 端数処理、適用順位） |
| 公式・手順 | 計算の手順を文章または式で示す |
| 代入と途中式 | 問題の数値を当てはめた過程（省略しない） |
| 答え | 最終金額・人数などと、正解選択肢との対応 |
| 落とし穴 | 端数切上げ/切捨て、小児・団体の扱い、適用外条件など |

**選択肢解説側**

- 正解: 計算結果が一致する旨＋一言で根拠
- 不正解: どこを誤るとその選択肢になるか（可能なら）を短く示す

**構成例**

```
【適用ルール】
…
【計算過程】
1. …
2. …
3. よって ○○円
【選択肢との対応】
…
【学習メモ】
端数処理は… / 類似の別パターンは…
```

---

## データ上の約束

- 選択肢キーは JSON 上 `A`〜`D`（試験冊子のア〜エに対応）
- 複数正解は `correctKeys` 配列。解説もそれに合わせる
- 解説未記入の間は `""` のままでよい（UI は「（未記入）」表示）
- 条文引用は可能な範囲で正式な文言に近づける。要約する場合は要旨である旨が分かる書き方にする

---

## 科目別の補足

| 科目 | id | 全体解説で意識すること |
|------|-----|------------------------|
| 旅行業法・施行規則 | `hou` | 条番号、登録行政庁、業種区分、期間・金額などの数字 |
| 約款 | `yakkan` | 約款の「部」名・定義、取消料・補償など表にしやすい数値 |
| 国内旅行実務 | `jitsumu` | **計算問題は計算方法・途中式必須**。適用条件・例外・端数処理も明記 |

---

## 作業手順（1問あたり）

1. `correctKeys` と問題文・選択肢を確認する
2. 根拠となる条文・約款・規則を確認する（推測で埋めない）
3. 各選択肢の `explanation` を書く
4. 全体解説で「制度の全体」→（計算問題なら「計算過程」）→「選択肢対応」→「学習メモ」を書く
5. アプリ上で表示を確認する（改行は `\n`）

---

## 品質チェック

- [ ] 各選択肢が「正解。」/「不正解。」で始まる
- [ ] 正解の選択肢説明と `correctKeys` が一致する
- [ ] 全体解説に、選択肢に無い重要項目が含まれている（列挙・定義系の問）
- [ ] ひっかけの言い換えを指摘している（該当する場合）
- [ ] 数字・条番号・行政庁名に誤りがない
- [ ] **計算問題**: 全体解説に公式・手順・途中式・最終答えがある（答えの暗記だけで終わっていない）
- [ ] **計算問題**: 端数処理・適用条件など、誤答につながりやすい点に触れている
